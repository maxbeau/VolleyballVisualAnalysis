# 🏐 Volleyball Visual Analysis (Pipeline Edition)

This project provides a modernized, modular pipeline for analyzing volleyball matches using computer vision. The entire workflow is orchestrated by a single configuration file (`pipeline.yaml`) and executed via a unified runner (`run_pipeline.py`), making it easy to manage, experiment with, and scale.

---

## ✅ Core Features

-   **Unified Pipeline**: All steps—from detection to final video overlay—are managed by a single, intelligent pipeline runner.
-   **Centralized Configuration**: No more scattered `.env` files or command-line flags. All settings for every module live in `pipeline.yaml`.
-   **Pluggable Backends**: Easily switch between detection backends (e.g., Roboflow cloud vs. local YOLO models) directly from the configuration file.
-   **Idempotent & Resumable**: The pipeline is designed to be resumable. Outputs from each step are saved, allowing you to tweak later stages and re-run the pipeline without reprocessing everything from scratch.

---

## 📦 Repository Layout

The refactored structure is centered around the `pipeline` module and the main configuration file.

```
.
├── pipeline.yaml             # The heart of the project - configure everything here
├── run_pipeline.py           # The single entry point to run the entire analysis
├── pipeline/
│   ├── config.py             # Pydantic models for validating pipeline.yaml
│   └── steps.py              # The implementation of each pipeline stage
├── volleyball/               # Core detection logic and backends
├── court/                    # Court detection and processing
├── players/                  # Player tracking logic
├── analysis/                 # Ball trajectory analysis
├── visualization/            # Video overlay and rendering
└── docs/
    └── PIPELINE.md           # Detailed guide to the pipeline architecture
```

## 🚀 Quick Start

Getting started is now simpler than ever.

1.  **Install Dependencies**
    ```bash
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -e .
    # For local YOLO, also install ultralytics
    # pip install ultralytics
    ```

2.  **Configure Your Run**
    -   Open `pipeline.yaml`.
    -   Set the `video_path` under the `global` section to point to your input video.
    -   Review the `steps` section to enable or disable the stages you want to run.
    -   Adjust any other parameters as needed. For a full explanation of all options, see the [Pipeline Architecture Guide](./docs/PIPELINE.md).

3.  **Run the Pipeline**
    ```bash
    python3 run_pipeline.py
    ```

That's it! The pipeline will execute the enabled steps in order, reading from and writing to the `output_dir` specified in your configuration.

## ⚙️ Configuration in Depth

All aspects of the pipeline are controlled by `pipeline.yaml`. This includes:

-   **Input/Output Paths**: `global.video_path`, `global.output_dir`.
-   **Detection Models**: Switch between `roboflow` and `local-yolo` backends, and specify model IDs or local file paths.
-   **Algorithm Parameters**: Fine-tune tracker settings, homography calculations, and trajectory analysis.
-   **Overlay Customization**: Control every visual aspect of the final rendered video.

For a comprehensive guide to all available settings, please read the **[Pipeline Architecture Guide](./docs/PIPELINE.md)**.

## ☁️ Running on Remote Machines

The new architecture is ideal for running heavy workloads on remote GPU instances (like autodl.com).

1.  **Sync Your Project**: Copy the entire project directory to the remote machine.
2.  **Install Dependencies**: Create a virtual environment and install dependencies as described in the Quick Start.
3.  **Configure**: Edit `pipeline.yaml` to point to your video file and select the appropriate detection backend (e.g., `local-yolo` with a powerful GPU).
4.  **Run**: Execute `python3 run_pipeline.py` inside a `tmux` or `screen` session for long-running jobs.
5.  **Sync Results**: Once complete, `rsync` the `outputs` directory back to your local machine for review.

## 🧱 Next Steps

With a robust and flexible pipeline in place, future work can focus on adding new capabilities:

-   **3D Pose Estimation**: Integrate a 3D pose estimation module as a new step in the pipeline, feeding world coordinates into the player tracking and action recognition stages.

The modular structure is designed for exactly this kind of piecemeal extension. If you have questions about integrating a new module, feel free to ask!
